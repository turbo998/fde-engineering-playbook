# 匿名旅行运营场景

版本 `0.1.0`，状态：实现用需求草案，基于已确认范围编写；不是已通过业务验收的应用。所有组织、角色、合同与金额为虚构合成数据，不对应真实政策。

## 业务目标与非目标

虚构分销商“星桥旅程”需要处理临近到店的住宿风险。运营人员林舟检查订单，运营审批人周岚批准替代，供给经理许宁负责供应商承诺。人物仅作角色示意，不创建真实账户。

目标是让风险处置、批准后的行程调整和供应商分析具有可追溯依据；不能以自动完成率替代安全性。没有可接受方案时，正确升级或拒绝也是有效交付。非目标包括真实酒店预订、真实外发、付款、生产身份接入、云部署和企业平台能力认证。

## 功能需求

| ID | 应用必须提供的行为 | 明确禁止或保留的未知 |
| --- | --- | --- |
| UC01 | 检查未来 72 小时到店记录，将缺失重确认与同物业近期取消相关联；列出事件时间与来源 | 风险升高不能直接写成“确定无法入住” |
| UC02 | 检索带版本和有效期的酒店合同、取消及赔偿条款；替代须同等级、同房型、满足入住人数、距离不超过 500 米 | 不降级，不忽略无效合同；未知库存不能确认 |
| UC03 | 所有替代确认先经运营审批；支持直接批准 A，或先有可追溯人工酒店核实事件再批准 B | 不接受请求 JSON 自报角色；隐藏按钮不等于后端授权 |
| UC04 | 仅交接已批准且实际确认的酒店、地址、到店事实和证据；继承已知信息 | 不能把建议当事实，不能再次索取已交接的确定信息 |
| UC05 | 只重排受影响的接送/体验，检查营业时间及取消条款；新增支出单独审批 | 容量未知保持 `capacity_pending`，不得标已预订 |
| UC06 | 聚合近 30 天供应商异常；区分直采与第三方证据，结合合同条款提出假设 | 稀疏样本不输出确定根因；相关性不等于因果 |
| UC07 | 供应商沟通只保留未发送草稿；承诺、供给来源及加价规则改变需供给经理单独批准 | 运营批准不继承为供给权限；不真实发送 |
| UC08 | UI/API 显示持久行动、证据、审批状态、交接来源与失败原因 | 不宣称原型身份是生产身份，不宣称 SQLite 审计不可篡改 |

“近期”的取消窗口、合成费用阈值、币种、容量和营业时刻由未来私有情景配置固定，不擅自发明组织政策。金额只使用整数最小货币单位；跨币种不能直接比较。

## 审批及一致性合同

每次批准绑定：可信会话的 actor、tenant、action、case、planVersion、policyVersion、proposedCost 与 factsDigest。批准前后改变事实、库存、方案、费用或政策版本时旧批准失效。过期时不得提交副作用；拒绝、取消、失效和过期均持久保存。

路径 B 的人工核实事件需包含操作者、时间、对象与来源，且绑定当前方案；不能用模型一句“已打电话”替代事件。验证事件不是自动批准。路径 A 与 B 均由候选应用后端验证运营审批角色、租户和案件范围。测试设施只提供可信合成身份声明的合同，不提供业务授权引擎。

事件 ID、幂等键与版本用于防重复及乱序；重启后审批、审计和已执行动作必须保留。重试不能重新消费同一批准或产生额外确认。运行状态区分 `running`、`awaiting_approval`、`completed`、`escalated`、`rejected`、`failed`；领域对象状态独立保留，不能以案件 `completed` 隐藏待容量确认。

## 模型与执行边界

未来批准后的应用须有真正的运行时推理，用于证据解释、计划建议和不确定性表达；执行与授权仍由应用决定。模型错误须有限恢复或显式失败，不用固定计时、静态成功结果或静默替身补位。四组独立实现提示词、编排、业务状态机、授权、存储、审计与界面；本阶段只定义合同。

真实推理、合成服务、离线替身必须在日志和结果类型中区分。取回的合同和供应商文本是数据，不可改变系统权限或指示泄露信息。只采集必要执行证据，不保存隐藏推理。
