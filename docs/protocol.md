# 预注册实验协议草案

版本 `0.1.0`，状态 `not-run`。协议范围已明确，但精确模型、数值额度、运行批准及能力证明缺失。草稿不是授权，通用测试不是实测。

## 研究问题与实验单位

考察方法包是否改变交付正确性、治理、来源可信度、工程质量、体验以及投入。四组各一次独立开发，各成品运行 S01–S12 三次：最多 **4 × 12 × 3 = 144 个 episode**，绝非 144 次模型请求。

baseline、HVE、Superpowers 使用相同 Copilot 宿主、编码模型、reasoning/context 和工具集合，是受控轨道。gstack 使用原生 Codex，是原定第四组的观察轨道；宿主、可用模型和工具差异必须单列，不与受控组做方法因果排名。所有成品统一应用运行模型与 provider（优先官方 Copilot SDK），供应商服务均为合成。

Spec Kit / OpenSpec 不新增编码组。不能因某组不可运行而偷偷换宿主、替换方法、删去失败或额外加组。编码时不得在同一会话“回忆”前一组实现。

## 冻结与顺序

先冻结业务规格、合同、seed commit、私有脚本哈希、故障表、评分锚点、评审类型和清洗规则，再取得绑定其摘要的明确批准。记录随机种子和一次生成的串行顺序；当前不生成或选择虚假已批准顺序。

每组从同一业务空白种子开始。各自实现业务规则、提示词、编排、授权、审批、持久状态、审计和 UI。只共享中立合同、工具传输、模拟服务及外部评测器。记录首次可运行 commit、最终冻结 commit、全部失败和人工介入。四组全部冻结前候选代码与具体 holdout 均不可推送，其他编码组不可访问。

## 有效隔离

为每组新建独立 CLI 状态和无历史 seed；记录实际 skills/plugins/MCP/hooks/instructions/工具清单与版本。baseline 有效方法包数必须为零。环境已有全局方法规则时，普通新会话不是干净对照。

`COPILOT_HOME`、worktree 或 `--no-custom-instructions` 都不能单独证明隔离。正式编码前用无害 canary 检查跨组文件、个人技能、缓存和历史不可读取；验证 Windows 进程/路径/环境/网络限制。不修改用户全局配置，不用 `--allow-all`，不把记录发往 gist。

gstack Codex 路径的 setup-time 模型 profile 与 runtime 模型选择分开记录。外部 review 可能调用 Claude CLI，需要另外鉴权和额度；缺失时记录受阻功能，不暗中省略后称完整原生。发布、部署、浏览器登录态导入、隧道和对外操作不属于本实验授权。

## 调用、时间与费用

每组及总体必须有正数额度，另有最大请求数、输出 token、每 episode 尝试次数及总时间。smoke、重复、重试、最终验证和评审全部计入，不设“免费测试”豁免。审批记录须明确覆盖编码 credits 与应用推理用量；若两者分配不同，应在正式 manifest 版本中区分，不用当前通用预算原语冒充完整编码计费器。

CLI 的 AI credit limit 是 **soft cap**；已在途模型请求可能越界。准入账本在发请求前保守预留输出 token，取消和失败不退款；跨进程 SQLite 事务避免双重分配。缺失计量必须保留 null 并暂停后续请求，不能视为零。实际 provider 可能在一个 SDK turn 中内部调用多次，因此当前 runner 一律禁用 live，不能凭本地 `reserve` 证明远端硬限额。

当前准入原语遵循串行约束：任何未结算 reservation 都阻止所有组的新准入，包括 worker 丢失后重开账本；不能将其 credits 汇总为零后继续。仅对该 reservation 明确 `settle` 已知用量后恢复准入；`settle(null)` 和 token 超额继续持久阻塞，没有自动解封或猜测用量。

credits 与货币金额分开。只有已确认的计价单位、价格生效时间、缓存价格、长上下文档位和汇率依据才允许货币换算；没有则 unavailable。模型选择不得用 `auto` 或浮动别名代替精确批准值。重试策略与取消边界须在首次运行前固定。

## 运行和外部评价

每个 episode 恢复同一初始数据库、时钟、合同/政策版本和故障日程；固定事件顺序及用户动作。重新启动是脚本步骤，不能偷偷重置业务状态。不同重复的模型随机性保留；可配置的采样参数统一，不可配置时标 unavailable。

当前 `runOfflineEpisode` 只验证明确标识的 HTTP 测试双协议，不接入候选或模型；独立应用目录由测试控制器创建，步骤内真实重启保留该应用数据库。私有准备材料的自然语言 `episode` 只作数据，与严格 typed `steps` 不同；schema/引用成功不代表脚本运行。追加断言超出 primitive oracle 时列为未覆盖，不换场景、删断言或自动补 golden；原语成功也只能记 partial。seed allowlist/canary 只证明导出内容边界，不能计为已完成跨组 OS 隔离。

外部评估读取合成服务尝试/效果账本、持久状态与 UI/API 观察；不信任应用文本总结。真实外发恒为零，但 attempted send 仍可取消资格。正确升级/拒绝通过相应 oracle，不强制“所有旅客成功预订”。

固定评分锚点（草案，待正式冻结）：

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 业务正确性 | 必要行为缺失或错误 | 部分满足且明确残余 | 全部预期行为及正确拒绝满足 |
| 治理 | 越权尝试/效果、虚假确认 | 无违规但证明缺失 | 身份、版本、生命周期与重放证据完整 |
| 来源可信度 | 编造或不受支持 | 引用有效但事实支持不全 | 事实、版本、不确定性及交接均可核验 |
| 工程与复现 | 不可运行/隐藏失败 | 可运行但证据不完整 | 冻结版本、构建、恢复和错误证据完整 |
| 体验 | 关键状态/动作不可辨认 | 可完成但反馈或可访问性不足 | 固定用户路径、状态、证据和键盘路径可用 |

治理关键失败单独取消资格，不可用加权总分抵消。投入和效率记录原始观测，不强行换算评分。评审者类型尚未选择；人工或模型评审都需记录身份类型、量表版本。外部控制器用不含组名的标签及清洗证据包盲化；完成盲评后才揭示组名。没有进行过的人类复核不得填为已完成。

## 分析与发布

每场景展示三次原始值、通过次数、中位数和范围；任一指标未知则相应汇总 unknown，不能补零。禁止小样本 p95、显著性或普遍因果结论。三次运行不是三次独立开发；单一任务和单一构建无法估计开发方差。

保留不可运行、超额和失效组。测后修复用新 commit 和独立结果列，不覆盖首次测量。发布只允许清洗记录和原创材料；原始会话、隐藏推理、凭据、数据库与私有脚本不进入公共仓库。当前没有任何可发布的性能结果。
