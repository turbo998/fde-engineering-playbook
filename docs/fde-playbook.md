# FDE 工程实践手册

本手册面向需要把模糊业务需求变成可验证交付的工程师。它是一套**待实测检验的工作方法**，不是当前仓库已具备全部业务能力的声明，也不是特定工具的安装指南。

匿名旅行运营案例包含三种业务职责：到店风险处置、批准后的行程重排、供应商异常分析。开发这些能力时使用的方法包，与应用内部的业务 Agent，是两个不同层次。

## 1. 把业务时刻写成可观察的问题

不要从“需要几个 Agent”开始。先回答：谁遇到了什么事件、现在如何处理、有什么可获得的证据、哪个决定必须由人做、怎样才算解决。

例如，“缺少酒店重确认”是可观察信号；“一定无法入住”是需要更多证据的结论。把两者混写，会让后续模型把风险描述成事实。

交付一份简短的问题说明：角色、触发事件、已有事实、未知信息、成功条件和非目标。未知政策应列为待确定项，不能由模型默认为客户规则。

## 2. 先划清行动与数据边界

在写提示词前确定：

| 边界 | 应有的可检查约定 |
| --- | --- |
| 数据 | 哪些是合成数据、哪些来自真实系统；何时采集、版本及保留范围 |
| 动作 | 只读、生成草稿、申请审批、允许执行的动作分别是什么 |
| 身份 | 谁可查看、谁可批准、哪一个租户/案件和行动属于授权范围 |
| 模型 | 可以提建议和整理证据，但不能自行赋予权限 |
| 外部依赖 | 哪些接口是真实、模拟、不可用或尚未接入 |

模拟通知服务应从设计上没有真实外发能力。即使业务逻辑出错，也不应给真实旅客或供应商发送信息。

## 3. 为事实、决定、动作分别建模

一个自然语言段落不能替代业务状态。至少区分：

- **事实**：库存、合同、到店时点、地址、容量，以及证据来源和版本。
- **建议**：候选替代、费用影响、需要人工判断的未知项。
- **决定**：谁在何时批准了哪个版本的哪项行动。
- **动作**：实际向哪个服务发出了什么请求，产生了什么结果。

“生成替代方案”不等于“替代酒店已确认”；“等待容量”不等于“体验已预订”；“供应商沟通草稿”不等于“沟通已发送”。

状态应由持久化记录和真实工具响应驱动，不由动画完成或模型写下“成功”驱动。

## 4. 把审批做成后端约束

提示词中的“需要人工批准”只能表达意图。最终执行前，后端还必须验证批准人、角色、租户、案件、行动、计划版本、成本版本以及是否过期。

等候审批期间，库存或费用可能变化。旧批准不应自动授权新方案。重复批准回调也不能产生重复购买。

原型可以使用合成身份，但必须标明它不是生产身份服务。不要接受浏览器请求体自称的管理员角色，也不要把隐藏按钮视为授权控制。

到店运营与供应商承诺使用不同的审批职责。一次运营批准不应被扩大解释成可以变更供给来源、调整规则或对供应商作出承诺。

## 5. 让业务 Agent 通过明确契约交接

一个建议的交接包应含案件标识、已批准计划版本、酒店/地址/到店事实、证据引用、允许动作以及仍待确认事项；不要传播多余个人信息或认证凭据。

接收方检查版本和授权后，只重算受到影响的环节。交接缺字段、版本过期或证据不足时，返回明确的拒绝或澄清原因，而不是从模型记忆补齐。

合同、邮件和检索文档是数据，不是高优先级系统指令。检索内容不能让应用绕过审批、改变权限或暴露其他案件信息。

## 6. 使用方法包，但保留自己的交付标准

HVE、Superpowers、gstack 可以影响工作节奏、上下文管理和验证方式；它们不能成为“测试失败但已遵循流程，所以交付成功”的理由。

根据证据缺口选择需要的阶段：已有研究足够时重用它；计划应给出可验证结果；实现需要实际运行；复核对照的是需求与证据，而不是文档数量。

团队采用方法包时先固定版本、了解加载范围，并验证它与现有 instructions、skills 和工具权限是否冲突。不要在全局安装多套规则之后把某次效果归因于其中一套。

## 7. 把评测放到生成过程之外

业务应用与生成它的 coding agent 都可能错误地声称成功。外部判分器应核对数据库状态、服务副作用、审批和来源，而非直接采信总结。

| 测量层 | 关注内容 |
| --- | --- |
| 开发过程 | 首次运行、返工、调用量、人工澄清、预算消耗、实际激活的方法 |
| 成品行为 | 需求满足、失败处理、审批正确性、证据质量、体验和运行成本 |

两层不能相互替代。一个成品运行很快，并不证明生成它的方法开发效率高。

共享契约和测试设施有助于公平比较；共享已经完成的核心业务逻辑则会把“独立实现”变成同一实现的包装。保留冻结候选及失败记录，修复后的结果另列。

## 8. 交付时明确能力、责任与残余风险

交付至少说明：如何启动、哪些依赖真实接入、哪些是测试替身、已运行哪些验收、哪些未运行、已知限制、模型和配置版本、谁负责批准后续真实动作。

模拟器测试通过只能证明在该模拟合同下的行为，不能证明真实酒店服务、企业身份平台或生产 SLA 已经验证。

公开材料使用原创匿名案例、合成数据和清洗结果。不要上传原始客户材料、密钥、原始模型会话、未清洗截图或带私人路径的故障日志。

## 何时暂停而不是继续“自动完成”

当权限、数据来源或成本授权不明确时，限制相应动作；可以继续其他独立安全工作，但不能把受阻动作改写成成功。

当找不到等效替代时，正确结果可能是升级给运营人员；当供应商根因证据不足时，正确结果可能是保留多个假设和一份未发送草稿。失败处理与不确定性表达也是交付能力。

本项目不会使用单一加权总分掩盖未经授权的副作用。比较应同时呈现正确性、治理、证据、工程质量、体验和投入。
